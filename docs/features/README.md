# Feature documentation

Create one English Markdown document per implemented feature, named `<feature-slug>.md`.

Each document should cover:

- Feature purpose and user-visible behavior.
- Main flows, states, and relevant edge cases.
- API and data contracts, including server or external-service dependencies.
- Required configuration, without secrets.
- Verification performed and its result.
- Known limitations, blockers, and pending integrations.

Keep the document aligned with the implementation. Do not describe planned or simulated behavior as implemented or externally verified.
